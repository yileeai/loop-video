# 制作与验收

## 对标分析

先探测分辨率、帧率、时长和声轨，再按内容节点抽帧。混剪切换时，如果顶部网格稳定且中部仍能看到运动细节，可用独立遮罩实现类似观感。记录能复刻的参数，同时区分画面观察和原工程推断。

竖屏样片的一种起点是 1080×1920、30 fps。内容卡约宽 90%，上沿在 19% 附近，字幕在 56% 附近，底片主要在下半幅可见。用户给了不同参考时按新的构图调整。

## ChatCut 方式

先确认可用连接和项目。用项目内真实的素材 ID 放置底片和旁白。分别安排混剪、遮罩、代码 MG 动画和字幕。使用当前宿主提供的直接代码创作接口及实时工具参数，给常改的文案和颜色留属性。用实际合成画面检查入场和稳定帧。

连接缺失时可交付本地可验证样片。用户需要后续进剪辑器时，附上底片段落、遮罩、旁白、字幕以及入出点表。只有实际写入并检查过的工程才称为 ChatCut 工程。

## 本地可运行模板

[render_motion.py](../scripts/render_motion.py) 用 Pillow 逐帧绘制前景，交给 FFmpeg 和底片、遮罩及旁白合成。它面向竖屏黑金信息卡。其他画幅或造型可适配脚本，沿用实际分镜和口播时间码。

准备三个文件：

- `base.mp4` 为按时码拼好的 1080×1920 底层混剪，时长覆盖旁白。宽屏素材可以缩放到填满下半幅、按主体偏移裁切，再补到整幅画布。也可以用整幅底片，前景会覆盖上半幅。
- `voice.wav` 为已锁定的 PCM 旁白。MP3 可先用 `ffmpeg -i voice.mp3 -c:a pcm_s16le voice.wav` 转换。
- `timeline.json` 为当前项目的口播时间码和动效内容。以 [示例配置](example-timeline.json) 为格式起点，替换成新视频的内容。

```bash
python3 scripts/render_motion.py --base base.mp4 --audio voice.wav \
  --timeline timeline.json --output preview.mp4
```

运行环境需有 Python 3、Pillow、FFmpeg 和能覆盖内容语言的字体。macOS 模板默认读取系统冬青黑体，其他系统用 `--font` 指定可用的 TTC 或 TTF。可选的 `--matte` 接收与画布一致的透明 PNG，省略时生成上灰下透的网格。加 `--speed 1.2` 可同步加速并保留旁白音高，默认按原速输出。

配置约定如下。

- `header` 和 `source` 分别是卡片顶栏和出处。无出处可留空。
- `scenes` 按 `start` 递增。所有时间以 1× 时间线的秒数为单位，第一幕从 0 开始。每幕持续到下一幕开始，最后一幕持续到旁白结束。
- `titles` 的 `at`、`text`、`y`、`size`、`accent` 控制标题入场和位置。模板坐标按 1080 像素宽画布。
- 可选 `counter` 包含 `at`、`value`、`unit`、`note`。滚动值只用于能核实的数字。
- `layout` 可以是 `chain`、`stack` 或 `tree`，分别是横向流程、逐层展开和分支节点。节点用 `at`、`title`、`detail`，分支图另给 `root` 及其出现时间。横向流程最多三个节点，逐层列表最多三行，分支图最多四个节点。
- `captions` 每项含 `start`、`end`、`text` 和可选的 `accent`。高亮部分接在普通文案后。每条控制在一行能读清的长度，长句拆成两条时间段。

## 转录口播（无文字稿时）

[asr.py](../scripts/asr.py) 用 faster-whisper 的 small 模型输出句级和逐字时间码（JSON），逐字时间就是动效的语义锚点。

```bash
ffmpeg -i 原素材.mp4 -ac 1 -ar 16000 -c:a pcm_s16le voice16k.wav
python scripts/asr.py voice16k.wav asr.json
```

安装：Python 3.8 用 `pip install --user --only-binary=:all: faster-whisper==1.0.3`（新版依赖在 3.8 上会编译失败）。首次运行会下载约 500MB 模型。small 模型中文同音字错误多（如「获客」→「霍克」、「客资」→「克资」），专有名词、数字、人名必须逐条校对，拿不准的在交付说明里列出来请主人确认。

## 浅底分屏口播模板

[render_split.py](../scripts/render_split.py) 直接读口播原视频（自带旁白），逐帧合成后输出带原声的 MP4，不需要另备底片和 wav。构图来自 2026-11-12 拆解的知识讲解类对标：

| 元素 | 参数 |
|---|---|
| 画布 | 1080×1920、30 fps，任意竖屏素材缩放铺满 |
| 分屏 | 上 0–960 米灰底 `(240,239,235)` 图解区；下 960–1920 人像，放大 1.08 倍、从 y=300 起裁（`frame()` 里的 `oy`，按人物头顶位置调） |
| 全屏段 | `layout="full"` 显示原画面，字幕在 y=1290 |
| 字幕 | 深灰圆角条压在分界线 y=960，46px 粗体白字，强调词用深底松绿 `#3CC48E`，每段可多个高亮片段 |
| 图解 | 墨黑 + 灰 + 浅底松绿 `#1F5C46`；顶部小字栏目名；元素按逐字时间码入场（淡入上浮、连线生长、点阵点亮、曲线绘出、数字滚动、打字） |
| 切换 | 场景之间硬切，跟对标一致 |

用法：

1. 复制脚本到工作目录，按口播改写 `sc_*` 场景函数、`SCENES`（起止秒、`split`/`full`、绘制函数）和 `CAPS`（起止秒、`[(文字, 是否高亮)]`）。时间全部取自 asr.json 的逐字时间码。
2. 先出静帧检查：`python render_split.py 原素材.mp4 pv --preview 1.9,4.5,9.0` 生成 `pv_<秒>.png`，看重叠、溢出、遮挡人脸。
3. 再出全片：`python render_split.py 原素材.mp4 成片.mp4`，然后 `ffmpeg -v error -i 成片.mp4 -f null -` 验证可解码，并抽 6–8 帧拼图检查动效确实在变。

字体默认 Windows 微软雅黑，macOS 自动回退到苹方 / 冬青黑体，也可用环境变量 `SPLIT_FONT_BOLD`、`SPLIT_FONT_REGULAR` 指定；顶部栏目名用 `SPLIT_TAG` 改。脚本里的示例场景（日历点阵、新闻列表、双曲线、点阵填充、评论区打字）可作为常用图解组件直接改用。

## 只改成片速度

现成视频无需重做动效。以下把带内嵌字幕的画面和旁白一起加速，按用户要求替换倍数和帧率。

```bash
ffmpeg -i input.mp4 \
  -filter_complex '[0:v]setpts=PTS/1.2,fps=30[v];[0:a]atempo=1.2[a]' \
  -map '[v]' -map '[a]' -c:v libx264 -crf 18 -c:a aac \
  -b:a 160k -movflags +faststart output.mp4
```

验证目标时长约为原时长除以倍速，再播放或抽查开头、中段和末尾。若另外交付字幕文件，把入点和出点除以同一倍速，保持顺序并校验末尾。
